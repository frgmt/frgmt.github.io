## なぜ作り替えるのか（現行サイトの実測値）

| シグナル | 実測 |
|---|---|
| **viewportタグが無い** | スマホ実機UA（375px）で `scrollWidth` **1,200px**。ブラウザが全体を約 **31%** に縮小して表示します。**これまで調査した中で最も縮小率が大きい**（他社は980px前後＝38%） |
| HTTPS非対応 | `http://` のみ。Chromeで「保護されていない通信」と表示される |
| **jQuery 1.9.1** | **2013年2月**のリリース。1.x系はサポート終了しており、既知の脆弱性が残っています |
| **`<h1>` が3個ある** | 1ページに複数のh1があり、何が主題か検索エンジンに伝わりません |
| 画像のalt属性 | 画像25点中 **23点に alt が無い** |

**この会社のサイトは、デザインそのものは新しいものです。**
大きな工場写真のスライダーがあり、お知らせも2026年8月まで更新されています。
問題は**スマホ対応が完全に抜け落ちている**ことに集中しています。

### 1,200pxを375pxに押し込むということ

viewportタグが無いため、iPhoneはPC用の1,200px幅のページを375pxの画面に縮小して表示します。
横スクロールは発生しませんが、**文字が約1/3以下のサイズ**になります。
せっかくの工場写真も、指で拡大しない限り本文が読めません。

## 設計上の判断

### 署名的装置 ── 圧縮コイルばね

バネ屋の提案なので、**圧縮コイルばねの側面図**をファーストビュー右側に置きました。
上が自由長、下が荷重時。**巻数は完全に同じまま、ピッチだけが詰まる**様子を描いています。

座標は目分量ではなく `x = x0 + w × (i/n)`, `y = y0 ± h/2` で機械的に生成し、
上下とも14セグメント（7巻き）で一致させました。
圧縮率は 188 / 300 = **62.5%**（実測）です。

実描画サイズは PC 400×250px（コイル 300×55px と 188×55px）／
スマホ375 302×189px／スマホ320 248×155px。

### 構造 ── 「巻き」で分ける

現行サイトから画素採取した青 `#6699cc` = `oklch(66.8% .094 249.4)` が基準です。
面 `oklch(45% .102 249)`、文字 `oklch(38% .094 249)`。**色相差 0.4°**。
元の彩度が既に低い（.094）ため、彩度を下げるのではなく明度を落として可読域に入れました。

249° は既存提案に最も多い青域です。そこで**構成原理で分けました**。
バネ屋なので「コイルの巻き（等間隔の反復）」を型にしています。

- **見出しの左に、等間隔の破線の縦罫**を必ず置く（`repeating-linear-gradient` で3px/4pxの反復）
- 5つのコア事業に 01〜05 の連番を通し、巻き数のように数えられるようにする

### 検査自体が機能していることの確認

「0件」が**検査の故障**による0件でないことを、先に確かめています。
既知の不良（viewportタグ無し・`#999` on `#fff` = 2.85:1・幅1600px固定・20pxのタップ対象）を
仕込んだページを同じ検査にかけ、**12件すべてを検出**することを確認した上で本番を測定しました。

### 数値を表す図形は、計算で照合しています

コイルの座標は**式から生成**し、上下の巻数が一致していること、
圧縮率が意図どおり（62.5%）であることを実測で確認しました。
目分量で置くと、巻数が食い違ったり圧縮率が狂ったりしても
見た目では気づけず、検査もすべて通ってしまうためです。

また、SVG内の文字は検査ツールが見ないため、
3つのラベルすべてについてコントラスト比を別途計算しています。
