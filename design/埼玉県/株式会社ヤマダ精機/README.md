# 株式会社ヤマダ精機 — トップページ リニューアル案

現行サイト（http://yamadaseiki.co.jp/）のリニューアル提案。トップページのみ。

## 見る

```
open index.html
```

ビルド不要。そのままブラウザで開けます。
※ 地図は Google Maps の埋め込みのため、`file://` では表示されません。
ローカルで確認する場合は `python3 -m http.server` 等で配信してください。

## なぜ作り替えるのか（現行サイトの実測値）

| シグナル | 実測 |
|---|---|
| **viewportタグが無い** | スマホ実機UA（375px）で `scrollWidth` **981px**。ブラウザが全体を約 **38%** に縮小して表示するため、本文がそのままでは読めません |
| HTTPS非対応 | `http://` のみ。Chromeで「保護されていない通信」と表示される |
| **jQuery 1.5.2** | **2011年3月**のリリース。**今回調査した中で最も古いバージョン**です。1.x系はサポート終了しており、既知の脆弱性が残っています |
| 画像のalt属性 | 画像50点中 **10点に alt が無い** |

**この会社の現行サイトは、内容が極めて充実しています。**
4つの「解決力」が丁寧に書き分けられ、被削材は材質記号まで列挙され、
設備は機種名・メーカー・台数・能力が表になっています。
**書かれている情報の質は、今回調査した中で最上位です。**

だからこそ、スマホで読めないことの損失が大きい構成です。

### 縮小表示であって、横スクロールではありません

viewportタグが無いため、iPhoneは981px幅のページを375pxの画面に押し込みます。
横にはみ出してはいませんが、**文字が約1/3のサイズになる**ため、
材質記号（SCM440、Ti-6Al-4V など）や設備の能力欄（1300/560/560）といった
**細かい英数字が最も読めなくなります**。この会社にとって最も重要な情報です。

## 設計上の判断

### 署名的装置 ── 5軸

この会社を一言で表すのは「同時5軸」です。
ファーストビュー右側に、**直進3軸（X/Y/Z）と回転2軸（A/C）**の軸構成図を
インラインSVGで置きました。

3軸の長さは目分量ではなく**すべて66pxに揃えて計算**しています
（実測差 0.5px）。軸の長さが不揃いだと機械の構成として誤った印象を与えるためです。
実描画サイズは PC 406×254px（回転軸の楕円 137×51px）／
スマホ375 302×189px／スマホ320 248×155px。

### 構成 ── 「5」を通す

現行サイトから画素採取した青 `#2166b3` = `oklch(50.9% .139 254.2)` が基準です。
面 `oklch(42% .118 254)`、文字 `oklch(36% .108 254)`。**色相差 0.2°**、彩度のみ抑制。

254° は既存提案に多い青域のため、**数の構成で分けました**。
同時5軸の会社なので「5」を通しています。

- 解決力4つ＋品質保証で**5節**（5節目だけ全幅にして締める）
- 被削材を**5系統＋鍛造/焼結**に分割
- 節番号は必ず **01〜05** の2桁

### 見出し

「5つの軸が同時に動くから、裏側まで削れます。」を h1 にしました。
現行サイトのキャッチは「ものづくり解決力。」で、
**何ができるのかが分かりません**（同時5軸の説明は本文の3段落目にあります）。

### 検査自体が機能していることの確認

「0件」が**検査の故障**による0件でないことを、先に確かめています。
既知の不良（viewportタグ無し・`#999` on `#fff` = 2.85:1・幅1600px固定・20pxのタップ対象）を
仕込んだページを同じ検査にかけ、**12件すべてを検出**することを確認した上で本番を測定しました。

軸の長さは**計算で照合**しています。目分量で置くと軸長が不揃いになりますが、
見た目では気づきにくく、検査もすべて通ってしまうためです。
SVG内の文字は検査ツールが見ないため、コントラスト比も別途計算しています。

また、設備表3つは `overflow-x:auto` の内側にあるため、
狭い画面では表の中だけが横スクロールします。
**ページ全体が横スクロールしていないこと**を、
スクロール容器の内側を除外して個別に確認しています。
