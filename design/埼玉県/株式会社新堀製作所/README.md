## 設計上の判断

### 署名的装置 ── 加圧力の階段

この会社の設備一覧を見て最初に目に入るのが、**60tから600tまでの幅**です。
小ロットの単発から大量生産の順送まで、
**加圧力の段のどこかに必ず居場所がある**ということが、この会社の売りです。

そこで、19台のプレスを能力順に並べた棒グラフを描きました。

**棒の高さは加圧力の平方根に比例させています。**
線形にすると600tに対して60tが10分の1の高さになり、見えなくなるためです。
**これは実際の比率を歪める表現なので、その旨を図の中に明記**しています。

描画後に実測し、**9本すべてが `118 × √(t/600)` と
小数第1位まで一致すること**を確認しました。

### 配色 ── 253だが、地と形で分ける

主色は現行サイトから画素採取した青 `rgb(14,115,209)` =
`oklch(55.6% .167 253.3)`。白地用に `oklch(43% .155 253)`。**色相差 0.3°**。

253近傍は既存提案に多い色域です。そこで次の軸で分けました。

- **地を無彩の紙色** `oklch(98.9% 0 0)` に（青みを一切入れない）
- **数値を等幅で右揃えにした「能力表」を主要な形**にする（6表）
- **区画の見出しに罫を引かず、01〜05 の番号で刻む**

### 見出し

「60tから600tまで。19台のプレス。」を h1 にしました。
現行サイトの h1 は会社名ですが、
**発注側が最初に知りたいのは「うちの部品が作れるか」であり、
それは加圧力の幅で決まります。**

### グリッド内の表について

前案（ノアエンジニアリング）で、`overflow-x:auto` を付けた表が
グリッド項目の `min-width:auto` に押されてトラックを広げ、
320pxで60pxはみ出す不具合を出しました。
今回は最初から `.grid2 > *{min-inline-size:0}` を入れています。
**スクロール容器を除いた実際のはみ出しが0件であることも別途測定**しました。

### 検査自体が機能していることの確認

「0件」が**検査の故障**による0件でないことを、先に確かめています。
既知の不良を仕込んだページを同じ検査にかけ、**12件すべてを検出**することを
確認した上で本番を測定しました。
